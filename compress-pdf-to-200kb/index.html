The 200 KB zone: single scans and small bundles

200 KB caps are the workhorse of Indian form attachments: marksheet scans, caste and income certificates, experience letters, two-to-four page bundles where the portal still draws one line in the sand. It feels like a roomy limit — until a colour marksheet arrives at 4 MB from the phone camera. The distance from 4 MB to 200 KB is about 95%, and it comes from two levers used together: pixel density (Extreme mode rasterises pages at web-appropriate resolution) and colour (the grayscale checkbox, which is where most of the remaining weight hides).

Work at 180, not 200

The same two-counting-systems problem as every cap: your file manager's “200KB” is bytes÷1024 rounded; the portal's 200 KB check may be 200,000 raw bytes. Files that sit on the ceiling fail intermittently — which is worse than failing loudly, because candidates re-upload the same file three times before suspecting the number itself. Compress to 180 KB and the ambiguity disappears. The tool above opens with Extreme pre-set; set your attention on the grayscale checkbox for anything that was ever photographed.

Bundles: compress parts, then merge

If the form accepts one combined PDF of, say, marksheet plus certificate, sequence matters. Compress each document individually first (each gets its own quality pass, and one colour-heavy page cannot drag the others), then merge them — merged size lands near the sum of the parts. Merge first, compress once, and the single heavy page decides everyone's fate. For forms asking per-document uploads, skip merging entirely and keep files separate and named by size (Marksheet_168KB.pdf).

Honest expectations

Text-born PDFs (created from Word, not scanned) shrink dramatically and stay razor sharp. Colour scans shrink to roughly the low-hundreds of KB with Extreme + grayscale; legibility of text, stamps and signatures holds at these sizes, but a heavily photographic page (a certificate with a large background image) has less to give. Read the tool's before/after display after each attempt — it reports real numbers for your file, which beat any range written on this page. Ranges here are typical outcomes, never promises; your file's number is the truth.

The grayscale question, answered honestly

Grayscale sounds destructive; for text documents it is close to free. A colour channel carries hue, not detail — a black-ink-on-white-paper scan has almost nothing in its colour channels except scanner noise and paper tint, both of which you want gone. Stamps and seals stay legible in grey (they were usually stamped in a dark ink that greyscales cleanly). The cases where grayscale does cost something: documents with colour-coded content — a coloured table, a red "ORIGINAL" overprint, a multi-colour logo where colour carries meaning. For those, try Extreme without grayscale first; if the number still fails the cap, weigh whether the colour is information or decoration. In our experience, form-attachment scans are almost always the latter.

Batch day: many documents, one sitting

If you are preparing five attachments for one form, set them up like a production line: compress each to its own working target, name each file with its size, run each through the Pre-flight Checker (it flags PDF encryption and page count too, not just images), and drop the verified set into one folder. The mistake batch-day candidates make is mixing workflows — resizing a photo between two PDF compressions, losing track of which file was compressed twice. One file type at a time, original to final, no re-compression ever. The portal's rejection message may be vague, but the cause is almost never mysterious: it is a number, a colour, or a page count.

3 common rejections — and their fix

“File size larger than the permitted limit (200 KB)”

Wajah: Colour scan compressed lightly, or the file sits exactly at the boundary where byte-counting conventions disagree (file manager says 200KB, portal counts 200,000 bytes).

Fix: Extreme + grayscale to an ~180 KB working target. Verify the tool's reported size, then the file manager's reading, before re-uploading.

“Combined attachment rejected / bundle too large”

Wajah: The merged bundle's weight is the sum of its parts — merging does not compress, so three colour scans combine into one file over the cap.

Fix: Compress each document separately first, then merge (merged lands near the sum of already-small parts). Or keep files separate if the form asks per-document.

“Document opens blank / 'invalid PDF' after upload”

Wajah: Portals re-parse uploads; heavily compressed colour pages can arrive where the portal's parser expects standard page structures — or the source PDF was already damaged.

Fix: Re-compress from the original (not the compressed copy re-compressed); for broken sources run Repair PDF first. Avoid compressing twice in a row.

Common questions

200KB wale form ke liye kitna compress karein?
Work at 180 KB — ten percent under the cap so file-manager rounding and portal byte counts both agree. The pre-set tool above loads Extreme automatically.
Marksheet ka size 200KB se kam nahi ho raha?
Colour scans need Extreme + the grayscale checkbox together; Recommended alone usually stalls in the several-hundred-KB range because it protects colour — the exact weight you're fighting.
Do documents ko ek PDF me kaise banayein?
Compress each first, then merge — merged size ≈ sum of the small parts. (Merge first, compress once, and the heaviest page sets the size for all of them.)
Grayscale karne se marksheet invalid to nahi ho jayegi?
No — grayscale changes colour channels, not content. Text, stamps and signatures remain legible; portals care about readability and size, not colour fidelity of a text document.
Kitne pages tak theek rahega?
Single pages almost always fit; 2–4 page bundles fit after per-part compression. Larger bundles usually mean the form actually wanted only one page extracted — check the instruction line.
Mera file manager 198KB dikhata hai, phir bhi reject?
The portal counts raw bytes its own way (often 1 KB = 1,000 bytes). Re-compress to ~180 KB: the margin absorbs the difference between the two counting systems.
